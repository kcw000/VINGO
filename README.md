# VINGO — VOCALOID BINGO

DJイベントやダンスイベントで、流れた楽曲をチェックして遊ぶ3×3のビンゴです。縦・横・斜めのいずれか1列がそろうと「VINGO！」になります。

待ち時間の楽しみ、一人で参加した人の会話のきっかけ、知らない楽曲との出会いを増やすために制作しました。ボカホール専用版から、イベントごとに曲や送付先を設定できる汎用版へ発展しています。

## 使用技術と構成

HTML / CSS / JavaScriptによる静的なブラウザアプリです。画面・スタイル・処理は `index.html` 内にあり、アプリ用のビルド工程は不要です。外部JavaScriptライブラリ、バックエンド、アカウント登録はありません。設定は利用中のブラウザのlocalStorageに保存します。GitHub Pages側の公開処理は別に行われます。

```text
├── index.html              # アプリ本体
├── ogp.png                 # 既存の公開用画像
├── README.md
├── AGENTS.md
├── CHANGELOG.md

```

## ローカル起動

GitとPython 3を利用します。すでにclone済みなら、リポジトリのルートでサーバー起動だけを行ってください。

```sh
git clone --branch main --single-branch https://github.com/kcw000/VINGO.git vingo_codex
cd vingo_codex
python3 -m http.server 8000 --bind 127.0.0.1
```

[http://127.0.0.1:8000/](http://127.0.0.1:8000/) をブラウザで開きます。終了はターミナルで `Ctrl+C`。Windowsで `python3` が使えない場合は、Python 3の導入を確認し、同じ引数で `py -3 -m http.server 8000 --bind 127.0.0.1` を使えます。

HTMLのダブルクリックではなくHTTPで開いてください。共有リンクは開いているページのURLを基に生成されるため、ローカルで作成したリンクは開発確認用です。参加者向けには公開サイトで作成したリンクを使用します。開発用の保存データは公開サイトと別になり、ホスト名・ポートが違う場合も共有されません。

## 基本機能

- 初期候補276曲、3×3カード、ランダム抽選、確定後のカード固定。
- マスのチェック切替、縦3・横3・斜め2の計8ライン判定。
- VINGO演出、達成日時、スクリーンショット案内、演出の再表示。
- シンプル・ミク・リン・レン・ルカ・メイコ・カイトの7テーマ。
- イベント名・主催者名・X / Instagram送付先・候補曲の設定。
- 共有リンクの生成、URLからの自動読み込み、リンク貼り付けによる読み込み。
- 盤面リセットと設定リセット。

QR参加と専用スクショモードは廃止済みです。SNSボタンは送付先ページを開くもので、画像やDMの自動送信はしません。

## 参加者の使い方

1. 主催者から受け取った共有リンクを開き、イベント名を確認する。
2. 好きなテーマを選び、「ランダム」で9曲を表示する。
3. 「確定」でカードを固定する。
4. 会場で曲が流れたら該当マスをタップする。
5. VINGOになったら画面をスクリーンショットし、主催者の案内に従ってSNSのDMなどで送る。

**現在は再読み込みでカード・チェック・成立日時が失われます。** テーマとイベント設定は残ります。途中再開機能は未実装です。

## 主催者の使い方

1. 公開サイトの「⚙️」からイベント設定を開く。
2. イベント名・主催者名・SNS送付先を入力する。利用しないSNSは空欄にする。
3. 候補曲を1行1曲で入力し、「保存」を押す。
4. 「共有リンクを作る」でURLを発行する。
5. 別ブラウザやスマートフォンで、イベント名・曲・SNS送付先を確認してから参加者へ共有する。

候補曲は、現状の運用では**異なる曲を9〜300曲**にしてください。入力欄は500曲まで保存できてしまいますが、共有先で300曲に切り詰められる不具合があります。重複曲も自動除去されません。上部のイベント名編集にも保存不整合があるため、当面は「⚙️」内で編集・保存し、共有先で確認してください。これらは未修正で、詳細は [課題一覧](docs/HANDOFF.md#未解決課題) に記録しています。

## GitHub Pagesへの公開

2026-11-09に既存設定を読み取り確認しました。公開元は **main / ルート `/`**、HTTPS有効、カスタムドメインなしです。設定を変更する必要はありません。

将来の公開は、次の順番で行います。

1. 作業ブランチで変更し、diffと [チェックリスト](docs/TEST_CHECKLIST.md) を確認する。
2. 変更内容・検証結果・未確認事項を報告し、依頼者が承認した操作範囲でcommit・push・PRを行う。
3. mainへの反映について明示的な承認を得る。mainの更新は公開サイトの更新につながる。
4. 承認後にmainへ反映し、GitHubのActionsでPagesのビルド・デプロイ結果を確認する。
5. 公開URLで主要操作と対象の表示を再確認する。

公開元を `docs/` や作業ブランチへ変更しないでください。将来テストを追加する場合は、テスト用ファイルをPagesの配信対象へ混入させない確認も必要です。GitHub上で閲覧できるリポジトリには、秘密情報や非公開のイベント資料を置きません。

公式手順：[GitHub Pagesの公開元設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
