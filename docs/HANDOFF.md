## 制作コンセプトと経緯

VINGOは、音楽イベントの待ち時間を楽しみ、参加者同士の会話や知らない曲への興味を増やすための楽曲ビンゴ。景品の厳密な抽選管理や不正防止システムではなく、会場体験を豊かにするお楽しみ企画として作られた。

Google Antigravityでボカホール専用版を制作し、実際のイベントで利用。その後、ビタミンV2など別イベントでも使えるよう、イベント名・主催者・SNS・候補曲の設定と共有リンクを備えた汎用版へ発展した。今後の改善・保守をCodexへ移し、完成済みの機能・デザインを維持することが今回の目的である。

## 現行の構成と画面

`index.html` 内にCSS、HTML、JavaScriptがある。初期曲データ `songsMaster`、ゲームの `state`、テーマ処理、上部のイベント名編集、`VingoSettings`、`BoardStore`、`ShareCodec`、`SettingsModal` が主要な構成要素。外部JSライブラリ、API通信、バックエンド、Service Workerは実装されていない。

画面は、タイトル→イベント名→テーマ→共有リンク貼り付け→ステップ表示→状態→ランダム・確定→ヒント→VINGO表示・演出再表示→カード→SNS案内→リセット・遊び方の順。設定ボタンは固定配置。VINGOバナーはDOM上ではカードより上にある。

7テーマはシンプル、ミク、リン、レン、ルカ、メイコ、カイト。テーマはカード内容を変えず、色を切り替える。QR参加と専用スクショモードは廃止済みで、関連する古いコメントやCSSが残っていても復活の根拠にしない。

## ゲーム仕様

- 初期候補は276曲で、初期曲名に重複はない。設定があればその候補曲を使う。
- `randomize()` はFisher–Yates方式で配列をシャッフルし、先頭9件を抽選する。同じ配列要素は重複しない。曲名の重複は保存前に通知して拒否し、自動除去しない。
- 確定前は引き直し可能。`lock()` 後は抽選を止め、マスのチェックを許可する。
- `checkBingo()` は横3・縦3・斜め2の8ラインを判定する。チェック解除後に成立ラインが0本になると成立状態も解除される。他の成立ラインが残る場合はVINGOを維持する。
- 最初の成立時に端末の `new Date()` を記録し、年月日・時分で表示する。成立を解除して再成立しても、盤面リセット等までは最初の日時が残る。
- 成立時はバナー、紙吹雪・クラッカー風演出、SNS案内を表示する。「演出をもう一度見る」も実装されている。
- 成立日時は端末の時計に依存し、秒表示やサーバーによる証明はない。厳密な先着順位の根拠にはできない。
- 設定保存成功後、開催IDと設定内容が同じなら盤面を維持する。変更があれば該当する別の盤面へ切り替え、保存済みのものがなければ空の盤面にする。保存失敗時は切り替えない。

参照：[ゲーム処理](https://github.com/kcw000/VINGO/blob/308d4726ab6400a557e2f3c1b9dccef115069caf/index.html#L2396)

## 主催者設定と共有データ

設定画面のイベント名は `maxlength=30`、主催者名は `maxlength=20`。Phase 3-Aの共有検証も同じ上限を使い、超過は切り詰めず拒否する。長さは既存UIに合わせたJavaScript文字列のUTF-16単位で、絵文字等の見た目の文字数とは異なる場合がある。

保存するJSONの代表例（架空の設定）：

```json
{
  "v": 1,
  "eventId": "0123456789abcdef0123456789abcdef",
  "eventName": "テストイベント",
  "organizerName": "テスト主催者",
  "xTarget": "",
  "igTarget": "",
  "songs": ["曲1", "曲2", "曲3", "曲4", "曲5", "曲6", "曲7", "曲8", "曲9"]
}
```

| 項目 | 現行の意味・挙動 |
|---|---|
| `v` | 数値の1のみ対応。省略時は旧リンク互換のため1。その他の値・型は保存前に拒否 |
| `eventId` | 新しい主催者保存時に生成する32桁の小文字16進ID。編集では保持し、全設定リセット後の保存では新規生成。旧リンクでは省略可。認証・秘密情報ではない |
| `eventName` | 30単位以内の文字列。省略時は `VINGO EVENT`。空文字は既存UIで保存可能なため受け付ける |
| `organizerName` | 20単位以内の文字列。省略時・空欄は名前部分を省略 |
| `xTarget` / `igTarget` | 文字列のユーザー名またはURL。空欄なら対応ボタンを隠す。省略時は既存の初期送付先。配列・数値等を拒否。URLの許可ドメインや新しい長さ制限は導入していない |
| `songs` | 文字列の配列。省略時・`null`は内蔵276曲。非配列や非文字列を含む配列は拒否 |

入力された候補曲は行単位で前後空白・空行を除く。保存・共有生成・共有読み込みはすべて9〜300曲、重複なしを検証する。超過や重複は日本語で通知して拒否し、無断切り詰め・重複除去・曲名変更はしない。過去に保存された301曲以上の設定は読み出して編集できるが、共有・抽選は調整を案内する。元の保存値は有効な設定で保存し直すまで残す。

文字項目の省略・空欄、全項目省略、候補曲の省略／null、旧クエリキーは引き続き対応する。設定全体の配列・null、不正JSON、未対応版、型不正は保存前に拒否する。保存失敗も呼び出し元へ返し、成功表示・盤面切替・自動再読み込みをしない。貼付失敗では入力画面と内容を維持する。

共有形式：

- 旧形式はUTF-8 JSONのBase64URLを `?v=1&cfg=...` で保持。`cfg` / `c` / `settings` と生のBase64設定コードを引き続き受け付け、旧形式の外側vの扱いは変えない。
- 新形式は同じJSON（内側 `v:1`、任意のeventId付き）を標準 `CompressionStream('gzip')` で圧縮し `?v=2&cfgz=...` とする。`cfgz` は外側v=2を必須にする。
- 圧縮API未対応、圧縮しても短くならない、生成失敗、上限超過なら旧形式を生成する。常に旧形式を選べる「互換リンクをコピー」も提供する。受信側未対応なら日本語で更新／互換リンクを案内する。
- 圧縮入力はBase64URL 65,536文字、展開後は256KiBまで。ストリーム読取中に上限を確認して停止し、UTF-8・JSON・設定を検証してから保存する。送信側も同じ上限を超えるgzipを発行しない。旧形式には今回新しい容量制限を加えない。
- Safari / iOS 16.4以降、Chrome / Android 80以降等の標準APIが対象。実機動作は別途確認する。[WebKit 16.4の公式説明](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/)
- 成功時は設定保存・画面反映後にクエリを除去し、約1.5秒後に再読み込みする。非同期解凍中の盤面操作は停止し、例外は画面通知に変換する。

圧縮は固定長の短縮ID方式ではない。設定全体をURLに保持するため長さの上限を保証できず、SNSやLINEがリンクを切断する可能性は実機検証が必要。暗号化・署名はないため、秘密情報を入れない。外部ライブラリ・サーバー・DB・有料サービスは追加していない。

共有ボタンは保存済み設定から生成するため、未保存の入力は共有されない。初期設定のまま生成すると `songs: null` が入る。`getCurrentSettingsForExport()` は初期曲を配列へ展開する関数だが、現在の共有画面はこの関数を使っていない。

参照：修正後は作業版の [index.html](../index.html) の `validateSettings()`。修正前の [VingoSettings](https://github.com/kcw000/VINGO/blob/308d4726ab6400a557e2f3c1b9dccef115069caf/index.html#L3123)・[URL適用処理](https://github.com/kcw000/VINGO/blob/308d4726ab6400a557e2f3c1b9dccef115069caf/index.html#L3323) は基準コミットの記録。

## 保存とリセット

localStorageは同一originのブラウザ保存領域で、別端末・別ブラウザに同期されない。設定JSONは現在の1イベント、盤面はイベント別のキーに保存する。

| 保存キー | 内容・扱い |
|---|---|
| `vingo_theme` | テーマ。盤面・全設定リセットでも残す |
| `vingo_settings_json` | 現在のイベントID・名前・主催者・SNS・候補曲。上部編集と設定画面はこの値を共用する |
| `vingo_event_name` | 旧形式。設定JSONがないときのみ読み込む。新規書込はしない。既存JSONの他の設定を失わず保存先を統一する |
| `vingo_progress_v1:` + 設定の正規化JSON | 盤面の版1、9曲のIDと曲名・順序、確定、9個のチェック、最初の成立日時（ISOまたはnull） |

識別キーは `[eventIdまたはnull, イベント名, 主催者名, X, Instagram, 有効な候補曲の順序付き配列]`。`songs:null`は内蔵曲へ展開する。URLの圧縮方式やBase64表現によらず同一設定を識別し、ハッシュ衝突にも依存しない。テーマは識別に含めない。キーは数KBになり得るが、外部DBや識別情報の別管理を不要にしている。

ランダム・確定・チェックの変更直後に保存し、起動時は共有設定の読み込み結果を確定してから該当盤面を復元する。VINGOはチェックから再計算し、成立日時を引き継ぎ、復元時に紙吹雪を再生しない。入力の版・型・件数・候補との一致・重複・日時を検証する。破損時は元の保存値を消さず空盤面と日本語通知で操作を継続できる。新たな抽選後はそのイベントの盤面保存値を更新する。

イベントAからBへ切替えてもAの盤面は残し、Aの同じ設定へ戻れば再開する。新しい開催は主催者が全設定リセット後に保存して新規eventIdを発行する。開催IDのない完全同一の旧設定を別開催として自動判別することはできないため、旧リンクを使い回す場合は参加者が盤面リセットする。設定内容を変えると同じIDでも別盤面になり、元の内容へ戻すと以前の盤面が復元する。

盤面リセットは現在の進行だけを削除。全設定リセットは現在の設定・旧名キー・現在と初期設定の盤面を削除し、他イベントの盤面とテーマを残す。上部の名前リセットは設定JSONの名前だけを `VINGO EVENT` へ変更し、他の設定を維持する（設定が変わるため盤面も切り替わる）。

複数タブではstorageイベントにより現在の設定と盤面を同期する。最後の書込が優先され、同時操作の履歴統合はしない。保存容量不足・保存拒否は通知し、設定保存失敗では入力と直前設定を維持する。途中経過の保存失敗ではゲームは継続できるが再読み込みで失う可能性を案内する。期限による自動削除や他イベントの一括消去は行わない。ブラウザ側の保存削除・プライベート閲覧終了・端末故障からの復旧は保証しない。

## SNSと演出の重なり

X・Instagramの設定値をプロフィール等のリンクに変換し、別タブで開く。主催者名は案内文へ反映する。空欄のSNSボタンは隠れるが、SNS案内欄自体はVINGO成立時に表示される。画像添付やDM送信は参加者が行う。URLの送付先ドメインが期待どおりかも検証対象にする。

演出には `pointer-events: none` が指定され、モーダル表示中は `body.modal-open` によりVINGO表示・SNS案内・演出を隠す。主なレイヤー値は通常UI 10、重要ボタン20、紙吹雪3000、演出文字3500、モーダル背景9000、本体9100、通知9200。個別の指定もあるため、変数だけを見て安全と判断しない。
